# 发送失败后重发剩余队列

- 状态：已实现（待手测）
- 背景：多文件排队时中途失败会清空整队，失败条只有当前文件「重试」，后面几个要重新选。
- 目标：失败时若队列里还有未发文件，失败条提供「重发剩余 N」：把当前失败文件与剩余路径一并重新入队。
- 非目标：自动重试；改单文件「重试」语义；断点续传。

## 用户故事

作为使用者，我拖了一串文件中途断了，希望一点把剩下的（含失败那个）再发一遍。

## 行为

1. 上传失败清空队列前：记下当前失败路径 + 当时剩余排队。
2. 失败条：保留「重试」（仅当前失败文件）；若剩余>0，另显示「重发剩余 N」（N=失败文件+剩余个数）。
3. 点「重发剩余」：按顺序入队（去重），走现有发送/忙时入队逻辑；不弹模态。
4. 仅失败文件、无剩余：只显示「重试」。
5. 落盘聊天记录保留 morePaths，重启后仍可点。

## 验收标准

- [ ] Q1：入队 3 个，第 1 个失败，条上有「重试」与「重发剩余 3」。
- [ ] Q2：点「重发剩余」三个会依次再发（对端可达时）。
- [ ] Q3：点「重试」只重发失败那一个。
- [ ] Q4：单文件失败无「重发剩余」。

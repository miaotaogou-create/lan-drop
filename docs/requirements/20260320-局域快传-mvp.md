# 局域快传（lan-drop）需求说明

- 状态：进行中（MVP：发现、聊天、单文件、网页共享已落地；文件夹未做）。A1 已于 2026-09-21 在 Windows（10.100.20.223）与麒麟（10.100.20.22）上对测通过。A4 大文件只在本机接口测过。
- 产品名：局域快传
- 仓库名：lan-drop
- 平台范围：Windows x64、银河麒麟等 ARM64 Linux（aarch64）
- 参考：既有 React UI 原型 `局域快传-(lan-drop)`；Gemini 界面稿（主界面 / 手动加节点 / HTTP 共享 / 设置）

## 背景

出差或厂区常需笔记本与目标机（含 ARM 麒麟）网线直连或同交换机互传文件、粘贴命令。飞秋好用但停更且闭源；LocalSend 可用但在旧 glibc 麒麟上有版本与字体坑。需要自研开源、不兼容飞秋协议的现代局域网工具。

## 目标

作为现场工程师，我希望在同一网段自动发现对端，聊天发文字（命令可复制），并高速传文件/文件夹，以便不依赖外网与微信/网盘完成交付。

## 非目标（本阶段不做）

- [ ] 兼容飞秋 / 飞鸽（IPMsg）协议
- [ ] iOS / Android 原生客户端（可用浏览器打开 HTTP 共享兜底）
- [ ] 云账号、中继服务器、跨公网穿透
- [ ] 完整复刻飞秋全部周边功能（白板、空间日志等）

## 用户故事

1. 作为用户，两端启动后能在设备列表看到对方（自动发现或手动加 IP）。
2. 作为用户，可向选定对端发送文本消息并在本地会话中看到收发记录。
3. 作为用户，可向对端发送文件或文件夹，对端落盘到下载目录，有进度与完成状态。
4. 作为用户，可在设置中改本机名称、监听端口、下载目录。
5. 作为用户，可手动添加跨网段/禁 mDNS 环境下的节点并测试连通性。
6. 作为用户，可开启本机 HTTP 共享，用浏览器或扫码拉取共享文件（无对端客户端时）。

## 验收标准

- [x] A1：两台机器同网段各运行一份程序后，60 秒内设备列表出现对端（名称或 IP 可辨认）
- [x] A2：支持「+ 加 IP」手动添加节点；提供连通性测试（如请求对端 `/api/info`）
- [x] A3：发送文本后，对端聊天区可见；UTF-8 中文正常
- [ ] A4：发送 ≥100MB 单文件，内存不明显随文件体积线性暴涨（流式）；接收方文件完整可读（流式落盘已实现，大文件需手测）
- [x] A5：设置中修改设备名与下载目录后重启或热更新生效（至少设备名对外可见）
- [x] A6：提供 Windows amd64 与 Linux arm64 构建产物（或脚本一键交叉编译）
- [x] A7：默认监听端口 8848（可配置）；README 说明防火墙需放行该端口
- [x] A8：开源仓库含 `docs/`、`README`、许可证，无闭源依赖阻挡构建
- [x] A9：可选择本机目录开启网页共享；同网段浏览器打开 `http://本机IP:端口/share/` 能看到文件列表并下载（无对端客户端时兜底）

## 约束

- 协议：自研现代方案（mDNS 或 UDP 发现 + HTTP JSON/流），不兼容飞秋
- 技术实现：Qt 5.14 Widgets。Windows 与 ARM 麒麟都是自己的窗口；安装目录自带 Qt 库，不依赖浏览器或 WebView2
- 文案与文档：简体中文

## 风险与依赖

- Windows 公用网络、第三方安全软件可能拦发现与入站端口
- 多网卡时广播/组播可能发错接口，需网卡过滤或绑定
- ARM 麒麟 glibc 为 2.31：用 Ubuntu 20.04 的 aarch64 工具链交叉编译，不依赖更新的 glibc
- 网页共享无鉴权，仅适合受信局域网；关掉共享即停止暴露目录

# 发文件夹仅顶层说明

- 状态：已实现（待手测）
- 背景：本阶段文件夹只发目录顶层普通文件、不递归；但「发送文件夹」与拖放成功时只说「开始发送文件夹（N 个）」，含子目录时用户易以为整树都发出去了。
- 目标：明确告知「只发顶层、不含子目录」；顶层无文件但有子目录时给出对应说明；含子目录时发送前可确认一次。
- 非目标：
  - 整树流式协议 / 网页共享规则变更（zip 打包发送见 `20260922-folder-zip.md`）
  - 改拖放协议（拖放仍顶层）

## 用户故事

作为使用者，我选了一个带很多子文件夹的工程目录发送时，希望软件说清楚只会发顶层那些文件，以免对方少文件还不知道。

## 行为

1. 「发送文件夹」选中目录后：
   - 顶层无文件且无子目录：仍提示为空。
   - 顶层无文件但有子目录：提示「顶层没有可发送的文件（子目录内容不会发送）」，不开始发送。
   - 顶层有文件且有子目录：确认框说明将只发顶层 N 个文件、不含子目录；取消则不发。
   - 顶层有文件无子目录：直接发，系统条写明「顶层文件」。
2. 开始发送时的系统条文案带「仅顶层 / 不含子目录」字样。
3. 拖放或粘贴文件夹进聊天：若展开了目录，系统条（多文件或单文件来自文件夹）标明仅顶层；不弹确认以免打断拖放。

## 验收标准

- [ ] D1：选仅含顶层文件的文件夹，系统条含「顶层」或「不含子目录」类说明并正常发送。
- [ ] D2：选顶层有文件且有子目录的文件夹，先确认；取消不发，确认后只发顶层文件。
- [ ] D3：选仅有子目录、顶层无文件的文件夹，有说明且不开始发送。
- [ ] D4：拖入含顶层多文件的文件夹，多文件系统条标明仅顶层。

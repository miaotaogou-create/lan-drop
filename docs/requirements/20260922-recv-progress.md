# 接收方气泡进度

- 状态：已实现（待手测）
- 背景：发文件时气泡有百分比；对方收文件时聊天区一直空白，大文件感觉像卡死，只能等全部写完才突然冒出卡片。
- 目标：对端开始传文件后，本机聊天区尽快出现「接收中 N%」文件卡，写完变为普通已收卡片。
- 非目标：
  - 接收失败后的重试按钮（另开）
  - 多文件并行各自独立进度条之外的高级调度 UI
  - 改传输协议
  - 自定义铃声

## 用户故事

作为接收方，我希望大文件进来时能看到进度，心里有数，而不是干等。

## 行为

1. 对端开始上传且本机能解析出文件名后：在对应会话插入 `InFile`，`progressPct` 从 0 起。
2. 接收过程中按字节进度刷新百分比（可节流，与发送侧类似，避免刷爆 UI）。
3. 写盘成功：该卡变为完成态（`progressPct = -1`），可打开/在文件 Tab 出现，行为与现网一致。
4. 文案：「接收中 N%」；进度条样式可与发送中一致或同色系。
5. 落盘 `chat.json`：仍跳过 `progressPct >= 0` 的进行中卡（与发送侧一致）。

## 验收标准

- [ ] R1：对端发较大文件时，本机聊天区在完成前出现接收中进度卡。
- [ ] R2：进度大致随传输前进（不必精确到每一字节 UI）。
- [ ] R3：完成后卡片可打开，文件在下载目录。
- [ ] R4：进行中卡不写入 `chat.json`；完成后写入。
- [ ] R5：`--self-check` 若可测则覆盖 InFile 进行中跳过落盘；否则本条仅手测。

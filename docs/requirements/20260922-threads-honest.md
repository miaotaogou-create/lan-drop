# 并发传输线程数诚实化

- 状态：已实现（待手测）
- 背景：设置里「并发传输线程数」可改可入库，但上传仍是单队列，改了没体感差异，属于误导。
- 目标：界面上标明当前未生效（灰显不可改 + 短说明）；仍展示已存数值；不实现真线程池。
- 非目标：
  - 真正的多线程并发上传池（另开大项）
  - 从配置文件删除 `transferThreads` 字段

## 用户故事

作为使用者，我不希望以为调大线程数就能传得更快，实际却毫无变化。

## 行为

1. 「并发传输线程数」输入框只读/禁用，仍显示当前配置值（默认 8）。
2. 旁侧或下方灰字说明：当前为单文件顺序发送，此设置暂不生效。
3. 保存设置时：不因该字段校验失败拦截；不改写用户无法编辑的值（保持 `m_settings.transferThreads` 原值即可）。
4. 不改变实际上传逻辑。

## 验收标准

- [ ] H1：打开设置，线程数框不可编辑，且有「暂不生效 / 单队列」类说明。
- [ ] H2：改其它设置并保存成功；`transferThreads` 仍为原值。
- [ ] H3：上传行为与改前一致（仍单文件排队）。

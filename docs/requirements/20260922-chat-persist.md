# 聊天记录落盘

- 状态：已实现（待手测）
- 背景：会话记录只在内存，重启或杀进程后清空，常用对端还要重新对一下上下文。
- 目标：把各对端最近聊天记录写入配置目录，启动时读回；每端仍最多 500 条。
- 非目标：
  - 云同步 / 导出完整归档
  - 搜索全历史、按日分页
  - 持久化进行中的上传进度条状态
  - 自定义铃声
  - 清空会话（见 `20260922-clear-chat.md`）

## 用户故事

作为使用者，我希望关掉再打开软件后，还能看到刚才和某台机器聊过的文字与文件卡。

## 行为

1. 存储位置：与 `settings.json` 同目录的 `chat.json`（一条文件，按 `IP:端口` 分会话）。
2. 写入内容：文字收发、文件卡（完成态）、系统/失败条等；**跳过** `progressPct >= 0` 的发送中文件卡。
3. 写入时机：有新消息入列或文件发送完成/失败撤卡后防抖约 0.5s 写盘；进托盘 / 退出时强制刷盘。
4. 启动：读入 `chat.json`，每端裁到最多 500 条；损坏或缺失则当空，不崩。
5. 进度百分比刷新**不**触发写盘。

## 验收标准

- [ ] H1：与对端互发文字后退出再开，该会话仍能看到这些气泡。
- [ ] H2：发送完成的文件卡重启后仍在，且可按原逻辑打开（路径仍有效时）。
- [ ] H3：杀进程前若刚发完，进托盘或退出后数据不丢（强制刷盘）。
- [ ] H4：无 `chat.json` 或内容损坏时启动正常，聊天为空。
- [ ] H5：`--self-check` 覆盖 chat.json 读写往返。

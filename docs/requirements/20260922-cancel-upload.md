# 取消当前发送与排队

- 状态：已实现（待手测）
- 背景：发错文件或队列塞太多时无法中途停；只能干等传完或关进程。
- 目标：发送进行中时，进度旁提供「取消」：中止当前上传并清空剩余排队。
- 非目标：
  - 只取消某一个排队项 / 调整顺序
  - 取消后自动重试
  - 接收方中途取消写入

## 用户故事

作为使用者，我拖错了大文件或排了太多队，希望一点就能停，不必等传完。

## 行为

1. `m_uploading` 时：聊天页与文件页进度文案旁显示「取消」按钮；空闲时隐藏。
2. 点「取消」：中止当前 HTTP 上传、清空 `m_uploadQueue`；进行中气泡去掉；系统条「已取消发送」。
3. 不弹模态确认（误点可再发；避免再挡进度）。
4. 取消后视为空闲，可立刻再发文件；不把取消记成可「重试」的失败条。
5. 对端若已收到部分数据：与现网 abort 行为一致（本轮不另做接收清理）。

## 验收标准

- [ ] C1：发大文件时进度旁可见「取消」；空闲时不可见。
- [ ] C2：点取消后当前传输停止，排队文件不再续传。
- [ ] C3：聊天出现「已取消发送」系统条；无「重试」失败条。
- [ ] C4：取消后可立刻再选文件发送成功。
- [ ] C5：文件传输页进度旁同样可取消（与聊天页一致）。

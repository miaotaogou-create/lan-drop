# 文件夹可打包 zip 发送

- 状态：已实现（待手测）
- 背景：仅发顶层易漏子目录；整树协议太大，zip 单文件可走现有上传。
- 目标：选文件夹时可选「打包为 zip 发送（含完整子目录）」；仍可「仅发顶层」。
- 非目标：递归流式协议、断点续传、zip 密码、网页共享改 zip。

## 用户故事

作为使用者，我传工程目录时希望整棵目录打成一个包发出去，对方解压即用。

## 行为

1. 「发送文件夹」选目录后：
   - 有子目录：对话框提供「打包 zip 发送」「仅发顶层」「取消」。
   - 顶层无文件但有子目录：仅提供「打包 zip」或取消（不再只能空手离开）。
   - 无子目录且有顶层文件：直接发顶层（行为不变）；可选不强制 zip。
2. 选 zip：本机临时目录生成 zip（系统 `tar`），再按单文件入发送队列；进度先提示「正在打包…」。
3. 打包失败：系统条说明失败原因，不开始发送。
4. 拖放文件夹：本轮仍仅顶层（不弹 zip，避免打断拖放）；zip 入口以按钮为准。

## 验收标准

- [ ] Z1：含子目录的文件夹可选 zip，对端收到一个 zip 且含有子目录内文件。
- [ ] Z2：仍可选「仅发顶层」，行为与旧版一致。
- [ ] Z3：仅有子目录、顶层无文件时，可通过 zip 发送。
- [ ] Z4：打包失败有提示且不入队。

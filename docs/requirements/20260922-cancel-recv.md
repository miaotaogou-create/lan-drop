# 接收中可取消

- 状态：已实现（待手测）
- 背景：发送可取消，接收大文件/错文件只能干等到完或关软件。
- 目标：接收进度时「取消」中止写入、删未完成临时文件，并记失败提示。
- 非目标：断点续传、通知对端友好取消协议字段。

## 用户故事

作为使用者，我发现对方发错大文件时希望立刻停掉接收，别占带宽和磁盘。

## 行为

1. 空闲接收（本机未在发送）时：进度区「取消」可见。
2. 点取消：断开当前正在落盘的接收连接；未完成文件删除（与断线失败一致）；进度清空；会话记失败/系统条。
3. 本机正在发送时：取消仍只停发送（发送优先，与现进度策略一致）。
4. 无接收时取消按钮隐藏。

## 验收标准

- [ ] R1：接收大文件中途点取消，进度停、未完成文件不残留（或已删）。
- [ ] R2：取消后聊天有失败/取消说明。
- [ ] R3：发送中取消仍只停发送，不误杀无关接收（若同时无接收则仅发送）。

## 影响范围

- `src/httpserver.*`（中止活跃接收）
- `src/mainwindow.cpp`（取消按钮与槽）
- `docs/test/mvp-cases.md`

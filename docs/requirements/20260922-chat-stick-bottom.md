# 聊天区贴底滚动

- 状态：已实现（待手测）
- 背景：发送进度会频繁整页重绘聊天 HTML，每次都强制滚到最底；用户上翻看历史时会被拽回去。
- 目标：仅在「本来就在底部附近」时自动跟到底；用户主动上翻后，进度/新消息刷新不打断阅读位置。
- 非目标：
  - 「有新消息」浮动按钮（已另开 `20260922-jump-bottom.md`）
  - 文件传输 Tab 单独滚动策略（可与聊天一致或维持现状）
  - 持久化每个会话的滚动位置到磁盘

## 用户故事

作为使用者，我希望传大文件时仍能上翻看之前的聊天，不要被进度刷新强行拉回底部；若我本来就在看最新消息，则继续自动跟着滚。

## 行为

1. 重绘聊天 HTML 前判断：垂直滚动条是否已在底部附近（距底约 80px 内，或无滚动条）。
2. 若在底部附近：重绘后滚到最新（与今日行为一致）。
3. 若不在底部附近：重绘后尽量恢复原滚动位置（钳制在合法范围），不强制到底。
4. 切换对端 / 初次打开会话：视为需要看到最新，滚到底。
5. 本规则适用于所有经 `refreshChatHtml` 的刷新（进度、收发消息、失败重试等）。

## 验收标准

- [ ] S1：发送大文件过程中上翻，进度百分比仍更新，视口不被拽回底部。
- [ ] S2：停在底部附近发/收消息或看进度，仍自动跟到最新。
- [ ] S3：切换到另一对端再切回，打开后在最新附近。
- [ ] S4：无足够内容产生滚动条时，行为正常不崩。

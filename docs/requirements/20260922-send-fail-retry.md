# 文件发送失败可重试

- 状态：已实现（待手测）
- 背景：上传失败后只剩居中红字，用户只能再点一次「发送文件」或重新拖放，大文件场景很烦。
- 目标：文件发送失败的提示旁提供「重试」；一点即对同一对端、同一本地路径再发一次。
- 非目标：
  - 文字消息失败重试（可再输入发送）
  - 失败后自动重试 / 断点续传
  - 队列里其余被清空的文件一键全部重发
  - 接收方进度、自定义铃声

## 用户故事

作为使用者，我希望文件传失败后直接点「重试」，不必重新选文件。

## 行为

1. 因网络/对端拒绝导致的文件上传失败：失败条展示原因，并带可点的「重试」。
2. 本地打不开源文件导致的失败：同样带「重试」（若文件已恢复可读则继续传；仍打不开则再出失败条）。
3. 点「重试」：对**当前会话所属对端**（失败条所在会话的 key）用原路径再走一遍上传；立刻出现进行中文件卡（与现有气泡进度一致）。
4. 若此时已有上传在进行：提示稍候，不打断当前传输、不清队列。
5. 重试不自动恢复失败时被清空的其余队列文件。
6. 源文件已删除或不存在：重试后给出失败提示，不崩溃。

## 验收标准

- [ ] R1：故意让上传失败（关对端或断网），失败条出现且可见「重试」。
- [ ] R2：对端恢复后点「重试」，出现进行中卡并最终传成功（或按现网完成态展示）。
- [ ] R3：上传进行中再点另一条失败的「重试」，不打断当前上传（有提示或无动作且可理解）。
- [ ] R4：源文件已删后点「重试」，有失败提示且程序不崩。

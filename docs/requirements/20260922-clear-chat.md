# 清空当前会话聊天记录

- 状态：已实现（待手测）
- 背景：聊天已落盘后，误发内容或过长历史无法去掉，只能手改 `chat.json`。
- 目标：在对端列表右键提供「清空聊天记录」；确认后清除该对端内存与落盘中的消息，不影响对端节点本身。
- 非目标：
  - 清空全部对端一键按钮（可后续）
  - 撤销 / 回收站
  - 删除本机已接收的物理文件

## 用户故事

作为使用者，我希望能清掉和某台机器的聊天记录，界面干净且重启也不会再冒出来。

## 行为

1. 在左侧对端上右键 →「清空聊天记录」（发现与手动节点均可用）。
2. 弹出确认：说明只清聊天、不删对端、不删已下载文件。
3. 确认后：移除该 `IP:端口` 在 `m_log` 中的全部消息；未读清零；立即写盘 `chat.json`；若正在看该会话则刷新为空聊天/文件页。
4. 取消确认则无变化。
5. 不清空时若该会话正在上传：本轮仍允许清空（进行中卡一并丢掉）；不强制取消网络上传（与现网队列行为最小改动；若上传完成仍可能再写入完成卡——验收注明：清空后若仍有进行中上传完成，可能再出现一条完成卡。更干净的做法是清空时若当前 key 正在传则提示稍候。采用：若 `m_uploading` 且当前选中即该对端，提示稍候不 Cleared。）

简化行为 5：清空时若正在向**该对端**上传，提示「请等待当前文件传完后再清空」；否则直接清。

## 验收标准

- [ ] X1：右键对端 → 清空 → 确认后聊天区为空，文件传输 Tab 也为空。
- [ ] X2：再退出再开，该对端历史仍为空。
- [ ] X3：取消确认后记录仍在。
- [ ] X4：清空不删除手动节点、不删下载目录里的文件。
- [ ] X5：对该对端上传进行中时点清空，有提示且记录未清。

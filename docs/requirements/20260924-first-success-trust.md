# 首次成功与可信赖（排障空态 / 失败可行动 / 大文件验收）

- 状态：实现中
- 背景：视觉打磨已过线；现场「第一次装能不能 10 分钟传成」仍卡在：看不到设备时不知如何排障、发送失败偏技术文案、MVP A4 大文件双机证据未闭环。本轮从产品可信赖切入，不再堆微交互。
- 目标：零设备时空态给出可执行排障；发送失败附带下一步；设置标明防火墙端口；补齐 A4 双机手测用例供验收回填。
- 非目标：首次运行向导弹窗；改发现协议；本轮不强制勾选 A4（需双机手测后回填）；远程桌面。

## 用户故事

1. 作为第一次使用的工程师，列表为空时我希望知道：要放行哪些端口、如何把本机地址给对方、如何手动加 IP。
2. 作为使用者，发送失败时我希望除错误原因外，还有一句可执行的下一步（检查在线/防火墙）。
3. 作为交付方，我希望有一份可照做的「双机 ≥100MB」验收步骤，测完就能勾 A4。

## 行为

### B1 零设备排障空态

1. 侧栏无设备：键帽「+ 加 IP」；脚注含同网段等待 + 放行 TCP 8848 / UDP 8850。
2. 主区未选设备：键帽「+ 加 IP」「本机」「防火墙」；脚注分三步（放行端口 → 复制顶栏本机地址 → 或加 IP）。
3. 发现端口异常时（状态非「自动发现中」）：空态脚注改为强调「仍可加 IP」+ 端口放行，不假装「正在发现」。

### B2 发送失败可行动

1. `noteFail` 对常见网络错误做简短中文归类（连接被拒 / 超时 / 主机不可达等），保留原细节。
2. 失败气泡末尾追加一句行动提示（如检查对方是否打开、防火墙是否放行 TCP 8848）；已有重试 chip 不变。

### B3 设置内防火墙提示

1. 设置页「本地 HTTP 监听端口」附近增加灰色提示：同网段需放行本机 TCP 端口与发现 UDP 8850（或当前 discoverPort）。

### B4 A4 双机验收用例（文档）

1. `mvp-cases` 增加双机 UI 发送 ≥100MB 手测步骤；MVP 文档 A4 注明「双机通过后勾选」。
2. 本轮不因仅有本机 API 测过而勾选 A4。

## 验收标准

- [ ] T1：零设备时主区空态可见三步排障与端口号
- [ ] T2：发现端口占用时，空态不再只写「等待自动发现」
- [ ] T3：人为制造发送失败（对端关闭或错误端口）后，失败条含可行动下一步
- [ ] T4：设置页端口旁可见防火墙放行说明
- [ ] T5：`mvp-cases` 含双机 A4 手测条目；MVP A4 仍为未勾直至双机通过
